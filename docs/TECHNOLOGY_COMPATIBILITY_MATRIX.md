Classification semantics:

- `PY314_NATIVE`: this is Python 3.14 itself, a bundled module, or explicit Python 3.14 package/build support is evidenced. Consult STATUS for whether runtime execution actually passed.
- `PY314_COMPATIBLE`: local execution passed, or universal/stable-ABI packaging or a protocol boundary provides a plausible path. COMPATIBILITY distinguishes proven execution from an untested candidate.
- `PY314_COMPATIBLE_WITH_NEWER_VERSION`: a specific older dependency needs replacement by a newer release with Python 3.14 evidence. No legacy version is silently promoted.
- `PY314_REQUIRES_BUILD`: the selected version/platform needs a source build; only use after measuring toolchain and maintenance costs.
- `PY314_REQUIRES_REPLACEMENT`: a selected dependency cannot satisfy the required interface on this platform and another implementation is needed.
- `PY314_UNKNOWN`: sufficient compatibility evidence has not been gathered. For external languages/services this refers to the planned adapter, not their ability to run standalone.

The final three remediation categories are available for future discoveries; absence of a package does not by itself establish incompatibility or a need to build it. No Python downgrade, GPU-stack upgrade, large engine installation or legacy dependency bulk-copy is justified by this matrix.

## Compatibility reconciliation

**OWNER_INTENT:** Python 3.14 first, several engines/databases/languages and GPU acceleration. **TECHNICAL_CONSTRAINT:** a package existing on PyPI or a standalone language executable being installed does not prove the desired adapter or GPU behavior. **OPTIONS:** install everything speculatively; change Python; or stage dependencies behind testable boundaries. **CHOSEN_COMPROMISE:** keep Python 3.14 and the existing PyTorch/CUDA/cuDNN stack; introduce only the driver needed for the bounded SQL proof; defer all other new packages until their corresponding feature is implemented. **REASON:** this preserves a working baseline and makes failures attributable.

**OWNER_INTENT:** GPU-capable feature pipelines. **TECHNICAL_CONSTRAINT:** the [official Polars GPU backend](https://docs.pola.rs/user-guide/gpu-support/) requires Linux or WSL2; its CUDA package also has a separate compatibility matrix. **OPTIONS:** CPU Polars on native Windows, future isolated WSL2, or another proven GPU engine. **CHOSEN_COMPROMISE:** CPU Polars is a future candidate; PyTorch remains the proven native Windows GPU engine. **REASON:** changing operating system/runtime boundaries is outside genesis, and Python 3.14 CPU compatibility is independent of RAPIDS support.

The local smoke tests establish a bounded baseline, not model accuracy, package-wide compatibility or a speedup claim. Missing integrations remain visible as deferred or unknown.
